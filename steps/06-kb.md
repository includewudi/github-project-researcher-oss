# Step 6: Update Knowledge Base

Simplified KB — single file, no PATTERNS.md.

## KB Location

```
~/.github-researcher/projects/KNOWLEDGE_BASE.md
```

## Pattern Worth Gate (MANDATORY before writing patterns)

Before writing ANY pattern, ALL 5 must pass:

| # | Question | Fail → Action |
|---|----------|---------------|
| 1 | Reusable across projects? | Skip — too project-specific |
| 2 | Novel? Already in KB? | Skip or link to existing |
| 3 | Named? Clear ≤5-word name? | Skip — too vague |
| 4 | Architecture-level? | Skip — RESEARCH.md only |
| 5 | Future value? | Skip — ephemeral |

**Throttle:** Max 3 new patterns per project.

## KB Hygiene Rules

1. **Append minimal non-empty entries only** — no "None found", no "N/A"
2. **Maintain index table at top** — one row per project
3. **Consolidation:** Trigger at >150 lines OR every 5 projects
4. **Deep-dive navigation:** KB gets verdict/insight/tags/link; details stay in RESEARCH.md

## Entry Template

Use `templates/kb-entry.md` for per-project entries.

## Simplified Flow

```
Research complete → Pattern Worth Gate → Append to KNOWLEDGE_BASE.md → Done
```

No separate PATTERNS.md. Patterns live inline in KB entries with `## 可复用模式` heading.

## Cross-Project Pattern Dedup

| Situation | Action |
|-----------|--------|
| Exact match | Add project name to existing pattern heading |
| Same family, new variant | Add project name + append variant |
| Truly novel | Pass Pattern Worth Gate → add new entry |
